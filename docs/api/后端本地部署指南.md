# MotiWish 后端本地部署指南

本文面向前端联调同学，目标是在本地启动 Django 后端、PostgreSQL 数据库容器，并访问 API 文档。

## 1. 环境要求

请先确认本机已经安装：

- Python 3.11 或 3.12
- Docker Desktop
- Git

可用以下命令检查：

```bash
python --version
docker --version
docker compose version
```

项目后端目录：

```text
backend/
```

本文所有后端命令默认在 `backend/` 目录下执行。

## 2. 进入后端目录

从项目根目录进入后端：

```bash
cd backend
```

## 3. 创建本地环境变量文件

在 `backend/` 目录下创建 `.env` 文件。

如果只是本地联调，可以使用以下配置：

```env
DJANGO_SECRET_KEY=dev-only-secret-key
DJANGO_DEBUG=true
DJANGO_ALLOWED_HOSTS=*

DB_ENGINE=django.db.backends.postgresql
POSTGRES_DB=motiwish
POSTGRES_USER=motiwish_user
POSTGRES_PASSWORD=motiwish_password
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5432
POSTGRES_CONN_MAX_AGE=60

TIME_ZONE=Asia/Shanghai
BUSINESS_TIME_ZONE=Asia/Shanghai

AI_PROVIDER=mock
AI_MODEL=mock-gpt
AI_API_KEY=
AI_BASE_URL=
AI_TEMPERATURE=0.2
AI_TIMEOUT=60
AI_MAX_RETRIES=2
```

说明：

- `AI_PROVIDER=mock` 表示本地不依赖真实大模型服务。
- 如果本机 `5432` 端口已被 PostgreSQL 占用，可以把 `POSTGRES_PORT` 改成其他端口，例如 `5433`。

如果改成 `5433`，`.env` 里需要同步写：

```env
POSTGRES_PORT=5433
```

## 4. 启动 PostgreSQL 数据库容器

在 `backend/` 目录下执行：

```bash
docker compose up -d db
```

查看容器状态：

```bash
docker compose ps
```

正常情况下会看到 `motiwish-db` 处于 running 或 healthy 状态。

如果想查看数据库日志：

```bash
docker compose logs -f db
```

## 5. 创建 Python 虚拟环境

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

macOS / Linux：

```bash
python -m venv .venv
source .venv/bin/activate
```

激活成功后，命令行前面通常会出现 `(.venv)`。

## 6. 安装后端依赖

```bash
pip install -r requirements.txt
```

如果下载较慢，可以换用国内镜像：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 7. 执行数据库迁移

```bash
python manage.py migrate
```

这一步会创建后端需要的数据表，并填充当前版本的默认商店商品。

## 8. 创建管理员账号

```bash
python manage.py createsuperuser
```

按提示输入用户名、邮箱和密码。

管理员后台地址：

```text
http://127.0.0.1:8000/admin/
```

## 9. 启动后端服务

```bash
python manage.py runserver 127.0.0.1:8000
```

启动成功后，常用地址如下：

| 用途 | 地址 |
|---|---|
| Swagger API 文档 | `http://127.0.0.1:8000/api/docs/` |
| OpenAPI Schema | `http://127.0.0.1:8000/api/schema/` |
| Django Admin | `http://127.0.0.1:8000/admin/` |
| API 前缀 | `http://127.0.0.1:8000/api/v1/` |

## 10. 前端联调登录流程

### 10.1 注册

接口：

```http
POST /api/v1/users/register/
```

示例请求：

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "Password123"
}
```

注册成功后，响应中会返回：

```json
{
  "access": "...",
  "refresh": "...",
  "user": {}
}
```

### 10.2 登录

接口：

```http
POST /api/v1/users/login/
```

示例请求：

```json
{
  "username": "alice",
  "password": "Password123"
}
```

### 10.3 调用受保护接口

后续请求需要在 Header 中带上：

```http
Authorization: Bearer <access_token>
```

## 11. 时间与定时调度

后端统一使用 `USE_TZ=true`，业务时区使用 `BUSINESS_TIME_ZONE=Asia/Shanghai`。`TIME_ZONE` 默认也会使用同一个值；服务器系统时间可以是 UTC，不影响业务日期判断。

前端提交精确时间时，请始终传带时区偏移的 ISO 8601 字符串，例如：

```json
{
  "due_at": "2026-06-06T17:18:00+08:00"
}
```

任务接口会按业务时区返回时间，同时数据库仍按 Django 时区机制保存时间。后端对 `due_at` 的解释规则如下：

- `2026-06-06T17:18:00+08:00`：按该明确时区解析，返回 `2026-06-06T17:18:00+08:00`。
- `2026-06-06T09:18:00Z`：按同一瞬间解析后转为业务时区，返回 `2026-06-06T17:18:00+08:00`。
- `2026-06-06T17:18:00`：没有 offset 时按业务时区理解，返回 `2026-06-06T17:18:00+08:00`。

前端不需要为了服务器 UTC 环境手动加减 8 小时。推荐仍然传带 offset 的 ISO 字符串；如果使用 JavaScript `Date.toISOString()` 得到 `Z` 时间，后端也会转回北京时间返回。

一次性任务超时同步命令：

```bash
python manage.py sync_overdue_tasks
```

只同步某个用户：

```bash
python manage.py sync_overdue_tasks --user-id 1
```

Docker 调度容器会按 `TZ=Asia/Shanghai` 运行：

- `DAILY_WISH_REFRESH_TIME`：每日愿望刷新时间，默认 `08:00`。
- `OVERDUE_TASK_SYNC_INTERVAL_SECONDS`：任务 DDL 超时检测间隔，默认 `900` 秒。

本地手动触发一次调度逻辑：

```bash
docker compose run --rm -e SCHEDULER_RUN_ONCE=true -e DAILY_WISH_RUN_ON_START=true scheduler
```

如果只想测试任务 DDL 超时同步：

```bash
docker compose run --rm web python manage.py sync_overdue_tasks
```

## 12. 导出 API 文档

后端启动后，可以导出 OpenAPI 文件：

```bash
curl http://127.0.0.1:8000/api/schema/ -o motiwish-openapi.yaml
```

也可以直接使用仓库中已导出的文档：

```text
docs/api/openapi.yaml
```

## 13. 重置本地数据库

如果只是想清空数据并重新迁移，可以执行：

```bash
docker compose down -v
docker compose up -d db
python manage.py migrate
```

注意：`docker compose down -v` 会删除数据库 volume，本地数据会丢失。

## 14. 常见问题

### 14.1 数据库连接失败

先检查容器是否启动：

```bash
docker compose ps
```

再检查 `.env` 中的配置是否匹配：

```env
POSTGRES_DB=motiwish
POSTGRES_USER=motiwish_user
POSTGRES_PASSWORD=motiwish_password
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5432
```

### 14.2 5432 端口被占用

把 `.env` 中的端口改成：

```env
POSTGRES_PORT=5433
```

然后重新启动容器：

```bash
docker compose down
docker compose up -d db
```

### 14.3 PowerShell 无法激活虚拟环境

如果出现脚本执行策略问题，可以临时执行：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### 14.4 忘记管理员密码

可以重新创建一个管理员：

```bash
python manage.py createsuperuser
```

或者进入 shell 修改已有用户密码：

```bash
python manage.py shell
```

```python
from apps.users.models import User
u = User.objects.get(username="你的用户名")
u.set_password("NewPassword123")
u.save()
```

## 15. 每次重新启动项目的最短流程

如果依赖已经安装、数据库已经初始化，日常启动只需要：

```bash
cd backend
.\.venv\Scripts\Activate.ps1
docker compose up -d db
python manage.py runserver 127.0.0.1:8000
```

macOS / Linux：

```bash
cd backend
source .venv/bin/activate
docker compose up -d db
python manage.py runserver 127.0.0.1:8000
```
